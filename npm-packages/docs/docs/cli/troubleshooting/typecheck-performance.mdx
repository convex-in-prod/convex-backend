When you are experiencing slow typechecking performance when pushing code to
your Convex deployment (e.g. when running `npx convex dev`), there are a few
different strategies you can try to improve performance or debug typechecking
bottlenecks.

## Application compiler

The CLI includes a pinned tsrs dependency and uses it for application
typechecks. Installing another TypeScript version in your project does not
change the compiler used by Convex. See
[Application typechecking](/config/convex.json#application-typechecking) for the
supported hosts and TypeScript semantics.

## Debug slow typechecking

Sometimes the TypeScript compiler can get stuck in a complex type inference
loop. Often, adding a single manual type can help break the loop. Run the
application check separately to reproduce its diagnostics:

```sh
npx convex typecheck
```

Consult tsrs's
[CLI usage and memory tuning](https://github.com/oxc-project/tsrs/blob/main/docs/USAGE.md)
for compiler-specific investigation. A trace from a separately installed tsc
does not measure Convex's application checker.

## Use static codegen

<BetaAdmonition feature="Static codegen" verb="is" />

[Using static codegen](/config/convex.json#using-static-code-generation-beta)
can improve typechecking performance, but currently comes with
[some caveats](/config/convex.json#using-static-code-generation-beta).

## Disable typechecking

You can disable typechecking using the `--typecheck=disable` option with
`npx convex dev` and `npx convex deploy`. In general, we do not recommend
disabling typechecking. However, this can be used as a last resort workaround.
